# Aeon 5.0 migration matrix

## Contract

Aeon 5.0 performs a read-only inventory of the existing `capacitor://localhost` IndexedDB, validates bounded pages and artifact descriptors, stages native catalogue rows and copied artifacts, then publishes them atomically. Adopted Documents paths remain references and are never copied or deleted. Embedded blobs are written through operation-owned incoming files and verified before publication. A failure must leave the existing native catalogue and legacy source intact.

Automated migration evidence ran in `AppTests` on iPhone 17 Pro and iPad Pro 13-inch (M5) simulators with iOS 26.5, Xcode 26.6 (17F113), and macOS 26.6.2 (25G83).

## Automated fixture results

| Fixture / failure mode | Assertions | Result |
| --- | --- | --- |
| Empty legacy library | Publishes an exact empty manifest and native publication marker; the source snapshot remains value-identical | PASS |
| Path-backed catalogue | Preserves stable album/track IDs and adopted relative paths; deleting native catalogue rows does not delete adopted bytes | PASS |
| Blob-backed catalogue | Materializes embedded audio and artwork, verifies byte count and CRC32, and converts the audio to a native Documents reference | PASS |
| Mixed path/blob/missing library | Publishes stable album and track order, duplicate playlist occurrences, play count, settings, log, last-played data, sky seed, sequence, and unknown future fields; missing media remains an explicit unresolved Documents reference | PASS |
| Interrupted artifact | Persists offset and sequence, resumes from the exact chunk after relaunch, and publishes without duplicate rows | PASS |
| 10,000-record library | Publishes 5,000 albums plus 5,000 adopted-path tracks with stable IDs; source snapshot remains value-identical | PASS |
| Bad chunk CRC | Rejects the chunk, keeps the checkpoint at offset zero, and does not alter source data | PASS |
| Publication conflict | Rolls back every row from the failed legacy publication and preserves the pre-existing native album | PASS |
| Actual Capacitor origin, seeded simulator | A hidden migration WebView reads seeded albums, blob/path tracks, playlist order, listening state, artwork, and audio from the same `capacitor://localhost` origin; the native manifest and copied bytes match and the legacy source manifest remains readable and unchanged | PASS |
| Legacy backup schema v1 and v2 | Native restore accepts existing JS-writer fixtures; invalid input cannot change the catalogue | PASS |

The installed-origin simulator test is an end-to-end test of the real WebKit origin and migration bridge, but it seeds an isolated test container. It is not evidence that a signed 4.x build was installed and upgraded in place on physical hardware.

## Source and output accounting

- Source: legacy IndexedDB rows and blobs under the existing Capacitor origin. Inventory collection is bounded and read-only.
- Adopted output: stable Documents-relative references only. Aeon does not create a duplicate and never treats the underlying user file as owned media.
- Copied output: embedded legacy audio and artwork are streamed into native-owned incoming files, size/CRC checked, then atomically published.
- Missing output: the stable track remains in the catalogue with its original relative path so the UI can report missing media rather than silently dropping history.
- Failure output: invalid pages, unsafe paths, duplicate pages, oversize data, bad CRC, and publication conflicts terminate without partial publication.
