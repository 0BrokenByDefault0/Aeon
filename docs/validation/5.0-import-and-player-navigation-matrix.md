# Aeon 5.0 import and player navigation matrix

Covers the three flows that failed physical-device acceptance for task 20: IMPORT FILES,
IMPORT FOLDER, and leaving an empty Player.

## What was wrong

| Flow | Defect | Cause |
| --- | --- | --- |
| IMPORT FILES | The button did nothing — no picker appeared | Three `fileImporter` modifiers were attached to the same root view. SwiftUI honours one and silently drops the rest, so only the last folder importer was ever live |
| IMPORT FILES | Supported files were greyed out in the Files browser | The picker asked for `public.audio` only. FLAC had no declared type in the bundle, so the system could not match `.flac` files to the request |
| IMPORT FOLDER | A chosen folder was unreachable on the next launch | The picker's security-scoped grant dies with the URL. No bookmark was persisted |
| IMPORT FOLDER | A folder of iCloud music scanned as empty | Directory enumeration used `.skipsHiddenFiles`, and an undownloaded iCloud item exists on disk only as a hidden `.<name>.icloud` placeholder |
| Both imports | Permission and location failures did nothing visible | The picker result's `.failure` case was discarded by a `guard case .success`, and `importLibrary` returned early without a message whenever the app was not ready or an import was already running |
| Player | An empty Player could not be left | The heading — which carries the close control — rendered only in the populated branch. The panel sits above Aeon's navigation chrome (`Layer.sheet` 30 over `Layer.chrome` 20), so nothing else was reachable |

## What changed

| Change | File |
| --- | --- |
| One picker presentation for all three journeys, backed by `UIDocumentPickerViewController` so cancellation and failure are distinguishable | `App/Import/ImportPicker.swift`, `App/Features/Root/AeonRootView.swift` |
| Content types resolved from every supported extension; FLAC declared as an imported type | `App/Import/ImportPicker.swift`, `App/Info.plist` |
| Folder grants persisted as security-scoped bookmarks, refreshed when stale | `App/Import/ImportedFolderStore.swift`, `App/AppContainer.swift` |
| Recursive discovery keeps iCloud placeholders and waits for their contents; hidden directories are still skipped | `App/Import/LibraryImporter.swift` |
| Unreachable locations, undownloaded iCloud files and pre-flight refusals each raise a distinct user-facing message, shown as an alert and inline on the sky and library surfaces | `App/Import/LibraryImporter.swift`, `App/AppContainer.swift`, `App/Features/Sky/SkyScreen.swift` |
| The empty Player renders its heading, close control and a labelled BACK TO AEON action | `App/Features/Player/NowPlayingView.swift` |

What they still cannot exercise: a real iCloud download, a real security-scoped grant
surviving a relaunch, a genuinely unavailable provider, and the behaviour of the Files
browser against a personal music folder. That is what the device matrix below is for.

## Running it on device

### Install

The `Build unsigned IPA` workflow publishes `Aeon-5.0-unsigned-ipa` as a run artifact.
It is unsigned on purpose: sideloading tools sign it with your own Apple ID on your own
machine. Install it with AltStore, SideStore, or Sideloadly as usual. Delete any earlier
Aeon first for rows 1 to 10, so the sky starts empty and the IMPORT buttons are on
screen; keep it installed for the relaunch rows.

### Prepare the test material first

Have these in place before starting, or half the matrix cannot be judged:

- **On My iPhone** — a folder with at least one MP3, one M4A, and one FLAC at the top
  level, for rows 2 to 5.
- **On My iPhone** — a folder with nested album subfolders (`Artist/Album/01 ….mp3`),
  for row 8. Include a `cover.jpg` in one album folder to check artwork pickup.
- **On My iPhone** — a folder holding only non-audio files, for row 10.
- **iCloud Drive** — an album folder whose files show the cloud-with-arrow badge, meaning
  they are not downloaded locally. If they have already downloaded, offload them with
  Files, long press, Remove Download. This is row 9 and it is the one most likely to
  expose a real bug.

### What counts as a failure

- The button does nothing, or a picker flashes and closes on its own.
- A file you can see in Files is greyed out and cannot be tapped.
- Import finishes and the sky or library is unchanged, with no message.
- Any message that says nothing actionable, or a spinner that never resolves.
- The empty Player leaves you with no way back except the system back indicator.

For each failed row, capture: the row number, what you tapped, what happened, and a
screen recording if the failure is visual. Settings, Diagnostics exports the log, which
is worth attaching for any import failure.
