# Aeon 5.0 SwiftUI screen and accessibility matrix

## Scope and environment

This matrix covers the native SwiftUI release surface. The normal app root is `AeonRootView`; the only WebKit controller instantiated by that production root is the hidden, migration-only reader described below.

Automated evidence was produced on this host:

- MacBook Air, Apple M5 (10-core), 16 GB memory
- macOS 26.6.2 (25G83)
- Xcode 26.6 (17F113)
- iPhone 17 Pro simulator, iOS 26.5
- iPad Pro 13-inch (M5) simulator, iOS 26.5

The Task 20 focused set contains 21 tests per simulator: 4 audio integration tests, 7 legacy migration tests, 5 accessibility UI tests, and 5 screen-matrix UI tests. The focused iPhone and iPad runs each completed 21/21 with no failures. The accumulated release run is recorded in `docs/releases/5.0.md`.

## Appearance and layout

`AeonScreenMatrixTests` launches every row on both simulator families, rotates each launch through portrait and landscape, asserts a native root with zero visible WebViews, and captures the result. Mean screenshot luminance must remain below the dark-surface threshold, including when the system requests Light appearance.

The automated matrix uses deterministic launch overrides: SwiftUI receives the requested content-size and color-scheme environment, while contrast, transparency, and motion overrides exercise the same consumer branches as their accessibility environment values. This is repeatable regression coverage, not evidence of toggling those settings manually in the Settings app on physical hardware.

## WebKit boundary

Capacitor and `app/legacy-migration.html` / `app/legacy-migration.js` remain in Aeon 5.0 only so an upgrade can read the existing `capacitor://localhost` IndexedDB. `LegacyMigrationViewController` starts at `legacy-migration.html`, reports the bounded inventory to native code, and is not a user-visible app surface. UI tests assert that the native root and every captured screen contain zero WebViews; the production SwiftUI root never loads the normal `index.html` app.

## Physical-device status

The connected iPhone was offline during this checkpoint and no physical iPad was available. Physical iPhone and iPad accessibility, rotation, focus, and visual review rows therefore remain **NOT RUN**. Simulator evidence is sufficient for the source/test checkpoint, not for physical-device release approval.
